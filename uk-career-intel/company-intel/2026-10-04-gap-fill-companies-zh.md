## 二、評級標準（與 Run 1、Run 2 相同；本輪補充另列）

**適配度（Fit）**（與 Run 1、Run 2 完全相同）：以 Dennis 的目標職類與技術背景對照該公司的業務與已知職缺。
- 高：業務屬軟體／雲端／AI／資安產品或工程，且與 Dennis 的 Go／TS／Python、雲端平台、資安背景直接對口。
- 中：屬軟體或雲端／資安相關，但偏顧問、合規或支援，或技術棧／職缺方向未驗證，或規模很小。
- 低：主要為管理式 IT／ERP 導入／非技術職，或業務內容在 verified3.md 中沒有足夠資料。
- Run 2 補充（沿用）：非 IT 核心機構依其已知 IT／軟體職缺是否對口判斷。

**申請難度（Difficulty）**（高＝較難；英國公司，與 Run 1、Run 2 相同）：綜合贊助狀態、現有職缺、公司規模與其他門檻。
- 中：有贊助資格但缺職缺，或有招聘管道但無贊助。
- 高：無贊助且無職缺／無招聘管道，或有明確限制（如僅限英國公民／永居、規模極小、明示不受理招聘詢問）。
- 低：需同時「有贊助」且「有確認開放的對口職缺」；本輪沒有任何一家符合（Run 1、Run 2 亦無）。

**東歐公司（Run 2 的量表，英國簽證贊助不適用）**：依「初階職缺」「語言要求」「遠端／搬遷可能性」「Dennis 為台灣身分」四點判斷：低＝有確認開放的初階或對口職缺、英語可應徵且有明確遠端或搬遷路徑；中＝有初階／對口職缺或入口但至少一項條件缺失；高＝無初階職缺或無招聘管道、或需要 Dennis 個人檔未列出的語言、或僅限到辦公室且搬遷資訊未找到；台灣身分是否影響僱用資格一律「未驗證」。**本輪 33 家已評級者皆為英國地點，不適用此量表**；FintechOS 的「羅馬尼亞總部」說法 verified3.md 未獨立核實（其英國法人為 FINTECHOS TECHNOLOGY UK LTD，控股公司在荷蘭），故仍以英國量表評級。

**排序**（沿用）：先依適配度，再依難度；同級再看「有確認開放的對口職缺」，其次「英國贊助資格」。

### 本輪新增的判斷規則（以下為報告撰寫者的判斷，不是 verified3.md 的事實，已在此揭露）

1. **「未檢查」不影響適配度的事實基礎，也不降低難度的贊助判斷**：入口無法載入時，職缺欄寫「未檢查」；難度仍依登記冊狀態與已知管道判斷（例如有贊助但職缺未檢查 → 難度「中」，與 Run 1「有贊助但缺職缺」同級）。若之後實查發現有對口職缺，才可能調整。
2. **公部門／機構的適配度**：只看 verified3.md 中**有證據**的 IT／軟體職缺或團隊。完全沒有 IT／軟體職缺證據者（博物館、美術館、國家圖書館、Glasgow City Council）判「低」，理由是「資料不足」而**不是**「確認沒有 IT 職缺」；這與 Run 2 把 Film City／Wardpark 判低的邏輯一致。
3. **大型雇主的難度**：以公司層級（是否有贊助、是否有常設招聘管道）判斷；畢業生計畫與 Dennis 入學時間的衝突**另設「時程適配」欄與專節**，不直接混進難度等級。
4. **截止日就是檢查日的職缺**（SPT Full Stack Developer，2026-10-04 截止）視為「不可行動」，在同級排序時不算「有確認開放的對口職缺」。
5. **同級排序**（例如 中／中 內部）的先後屬判斷，差距不大。
6. **適配度「高」門檻**：技術棧幾乎都是「未驗證」，本輪沿用 Run 1 的做法——軟體／雲端產品或顧問公司且有工程類職稱證據者判高（Scott Logic、Made Tech、Ometria）；證據只涉及顧問或非工程職者判中。
